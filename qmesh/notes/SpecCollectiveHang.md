# TP2 speculative collective hang investigation

The hybrid speculative long-context hang reproduced **after generation**, at the final process-group barrier, in `deadlock_graph_k5_01`. Both ranks printed 64 generated tokens and `SEG_REPLAYS 0 1702`; after 600 seconds both GPUs held 95,049 MiB and showed 0% utilisation. Both rank logs ended at the NCCL barrier warning. Host `py-spy dump` was attempted before killing both runner processes but was denied permission, so no stack was obtained. This establishes a hang, not its exact internal NCCL stack.

Both ranks issued matching traced host-side collective sequences, including at step 54, sequence 3849: `all_reduce shape=(1, 4, 5120) dtype=torch.float32 bytes=81920 transport=nccl capture=True`. Thus NCCL was demonstrably captured; graph B calls the MoE forward and its TP reduction inside the segment. NCCL capture is a documented hazard on this box and is a strong candidate for the subsequent barrier hang, but this observation alone does not prove causality. Capture does not necessarily hang immediately: this run completed generation. Replays do not generate host-side trace entries. Avoid NCCL inside CUDA graphs. The hybrid backend now routes captured all-reduces to the chunked P2P implementation, and NCCL backend entry points reject capture. Speculation with hybrid is additionally rejected at startup pending validation; use `COMM=p2p`. P2P avoids the captured NCCL path, but is not proven immune to all possible collective mismatches.

At 65,536 context, 20,000 requested prose filler, 24,167 actual prompt tokens, `MAX_CHUNK=2048`, `MAX_NEW=64`, `IGNORE_EOS=1`, batch 1, tracing enabled and graphs off, three hybrid K=5 runs each had 5,320 matching traced calls (1,900 NCCL, 3,420 P2P) and 42 matching confidence windows; one K=3 run had 4,620 matching calls (2,337 NCCL, 2,283 P2P) and 35 matching windows. No rank divergence appeared. A shorter graphs-off K=5 run stopped at EOS after 8 tokens, with 1,620 matching calls and 5 matching windows. The graph-on run used the same long-context settings and K=5. These deterministic repeats cannot bound all workloads or races. Rank-local confidence decisions can still differ; a 3-row fp32 reduction is 61,440 bytes (P2P), versus 4 rows at 81,920 bytes (NCCL). A mismatch can therefore split transports, and even a fixed transport alone cannot repair differing collective shapes or counts.

Runs used `TORCH_CUDA_ARCH_LIST=12.0a` and `EXL3_DSV4_B1_BATCH=1`. Logged host collective counts omit graph replays. The requested p2p/nccl by K=3/5 matrix and a raised-threshold control were not run; the post-fix guard and routing change have not been validated on hardware.
